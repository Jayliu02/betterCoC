# MuMu 实测记录

## 连接

MuMu 15 的 ADB：

```text
C:\Program Files\Netease\MuMu\nx_device\15.0\shell\adb.exe
```

设备串口：

```text
127.0.0.1:16384
```

`adb devices` 同时会看到 `emulator-5554` 和 `127.0.0.1:16384`，两者指向同一台设备。配置里使用后者，避免模拟器重启后 emulator 编号变化。

`bettercoc` 的 `AdbDevice.resolve()` 会自动执行 `adb connect`，因此每次 CLI 启动时不需要手动重连。

“战斗”按钮的图标会随游戏状态变化（剑 / 宝箱 + 绿勾），所以主城判断不再依赖整块按钮模板，只校验按钮底部的黄色条。回主城流程在 `bettercoc/recovery.py`，依次处理侧栏、欢迎弹窗、侦察/战斗“结束战斗/放弃”和“确定”、退出弹窗“取消”、结算“回营”，最后确认主城；画面切换中等待，战斗里按返回无效的问题由此规避。

侦察界面的按钮整排会随状态变化：有“复制阵型”时“自动战斗”在右侧，没有时整排左移，所以 `auto_battle` 用限定 ROI 的模板而不是固定坐标。

## 自动战斗不可用

2026-11-24 22:57 起，侦察界面只剩“结束战斗 / 军队已强化 / 英雄已强化 / 复制阵型（有时有）/ 下一个”，没有“自动战斗”，重启游戏后仍然如此；1 月份的截图里该按钮还在。这是游戏账号状态变化，不是脚本问题。当前处理：

- `_raid` 等 5 秒拿不到 `auto_battle` 就结束侦察、回主城，并直接报错提示
- 报错信息提示改用 `task.raid.army.troop_slots` / `deploy_points` 手动下兵

要恢复自动刷资源，需要先在游戏内把“自动战斗”恢复出来；否则只能补手动下兵坐标和 `scout_attack`、`battle_end`。

## 操作时的界面行为

- 打开建筑或城墙面板后，点击面板外会选中其他建筑，主城 HUD 不响应
- 面板打开时按返回键会弹出“确定退出游戏？”对话框，取消后游戏不会退出
- 重新启动 CoC 会弹“欢迎回家”公告，需要先关闭后再识别主城
- 重进游戏后固定弹“欢迎回家”开屏面板，右上角红色 X 可关闭，`home_popup_close` 命中 1.000
- 长时间无操作会弹“还在吗？”断线弹窗，点“重新载入游戏”后回到主城
- 主城底部按钮和面板的位置在 1920x1080 下稳定，但选中建筑时镜头会轻微平移

因此 `prepare` 状态需要优先识别 `home_attack`，并在必要时用 `home_popup_close` 关闭欢迎弹窗，用 `side_panel_close` 关闭侧边面板。
